# MessageThread

The follow-up told as a letter-style timeline: each turn has a mono timestamp and channel chip in the margin, a mono sender label, and the message. System events sit centred in mono between turns.

- This is the flat "notepad" pattern from the product's client chat, used for storytelling. Keep sender labels on every turn; flat isn't structureless.
- Mix channels in one thread (Email, SMS, Portal chat) — that's the point.
- End on a system event that shows judgement ("AI held the reply — no grounded answer, flagged for a person", "Cadence exhausted — moved to triage as stalled"). It's the most persuasive line on the page.
- Three to five turns. Timestamps realistic and in order; nudges at 09:00 client time.
- Consumer provides: turns (time, channel, sender, message) and optional system events.
